# O3-C6-E5-F1 增补：挂点修正、FFS GUID 识别与容量边界

## 1. 挂点修正（P0）

原设计把 `continue` 放在 `CoreDispatchEventNotifies()` 的 `NotifyFunction` 之前，这是
错的：该函数在调用通知前 `CoreReleaseEventLock()`，调用后必须
`CoreAcquireEventLock()` 才能继续循环。直接 `continue` 会跳过重新加锁，破坏事件
队列锁状态。

修正后的挂点在 **`CoreNotifySignalList()`**（Event.c:246）：只对 EBS 事件组抑制
`CoreNotifyEvent(Event)` 入队，分发器逻辑与锁生命周期完全不动。这也与同型号实验
的实际位置一致（其 `SKIP_ALL` 控制的是是否调用 `CoreNotifyEvent`，不是分发循环）。

```c
if (KebabEbsFilterShouldSkip (&Event->EventGroup,
        (UINT64)(UINTN)Event->NotifyFunction, (UINT64)(UINTN)Event)) {
    continue;              /* 不入队，锁仍由 CoreNotifySignalList 持有 */
}
CoreNotifyEvent (Event);
```

## 2. 镜像识别（P0 修正）

不再使用 DevicePath 字符串。DXE 驱动的末端 DevicePath 是
`MEDIA_PIWG_FW_FILE_DP`，里面是 FFS 文件 GUID。改为：

- 在 `CoreLoadImageCommon` 记录 `(ImageBase, ImageSize, ImageHandle, FfsGuid)`；
- 只登记 FFS GUID 等于 `cb29f4d1-7f37-4692-a416-93e82e219766` 的镜像；
- 判定时要求 `NotifyFunction ∈ [base, base+size)`（用 `addr - base < size` 防溢出）。

`KEBAB_FILTER_MAX_IMAGES` 满时返回失败并置 `kebab_filter_capacity_hit()`，不再
静默丢弃。

## 3. 记录器衔接（P1）

“E3 → E7(status=SKIPPED)” 不应把未执行的回调记成已返回。改法：在
`KebabEbsProbe` 增加独立阶段码 `KEBAB_EBS_E3_SKIPPED`（追加在枚举末尾，不改现有
值），只在回调入口、身份匹配通过且决策为跳过时写入。E7 仍只表示真实返回。
