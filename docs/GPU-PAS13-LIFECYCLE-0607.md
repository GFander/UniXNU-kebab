## Timing decision for implementation review

Alioth calls GPU context and CP start before `zapLoad()`. Copying that order would violate kebab's existing rule that PAS memory preparation precedes graphics VM publication. The original `KF_OP_PAS13_SEPARATE_IMAGE` slot1 exclusion must remain intact.

The initial host-only 0607 lifecycle proposal performed all calls after CP and included an image-load callback after MEM_SETUP. That proposal is **not approved for native integration**: it cannot satisfy both ordering constraints. Its host receipt and original files are retained, not rewritten as a successful native lease.

Develop two explicit phases, without weakening the old gate:

1. After original GMU/HFI initialization, before any slot1 reservation: acquire canonical parent/resource readiness and the unchanged generic pre-VM PAS lease; perform fresh NC/owner/range checks; freeze metadata; once INIT, once MEM_SETUP; on two definite zero/zero returns, load/zero/verify only the image. Freeze image as soon as this preparation is finished. Release only the temporary namespace serialization, retaining permanent memory ownership and the **same SCM transaction token on the same normal thread**. Any attempted but incomplete preparation blocks graphics VM publication.
2. That same worker calls the existing graphics VM/GX/OOB/CP initializers only after completed preparation, with no further low-memory CPU access. After fresh canonical CP proof, the authentication phase permits **no memory preparation or namespace mutation**; once AUTH, record raw result and transaction end. Success alone permits the later secure-exit test. Original immutable VM/OOB/CP receipts remain independently retrievable. No external USB initializer is interleaved with this worker.

Linux exposes PAS initialization/loading separately from authentication; its generic MDT path does not require an existing GPU VM or CP token for the first two calls. Splitting at this boundary is a source-backed interface adaptation, **not yet kebab hardware qualification**. Kebab's existing `KebabScmPasWorker.h` additionally requires one token for the complete domain lifecycle; preserve that stronger rule. Audit the reused VM/OOB/CP call graph for SCM recursion and lock inversion before integrating it. Early INIT/MEM timing and the interval between preparation and AUTH must be tested once under watchdog/recovery gates. It must not be described as an alioth-proven sequence.

Every old CPU preparation entry must refuse new memory access once INIT can have transferred metadata ownership. Cached immutable CAP44/NC/RAM receipts remain readable; their getters are not live-memory probes. Subsequent validation must not hash or read frozen low-memory buffers. Future GPU memory is managed high RAM and must remain disjoint from both retained low grants. Do not change canonical SMMU publication, CPU display, IRQ mask, or the original render packet stream to accommodate PAS.

## Physical acceptance and failure boundaries

Use one builder, one serial owner, exact source/native/image hashes and boot_b gates. Test preparation and authentication independently, with INIT/MEM/AUTH raw transport/peripheral/type/data/cookie, attempt/resume counts, time, guard, software freeze state and explicit HYP UNKNOWN fields. A nonreturning SMC is not bounded by a cooperative elapsed-time check; watchdog and confirmed physical recovery remain required. No automatic repeat of a call which might change HYP ownership.

On successful authentication, verify original Root/nonce, bank/systembag, encrypted Data, MACF/ACL/Sandbox, original watchdog and GPU baseline after the operation as well as the boot safety window. Request new manual GUI checks for the actual new boot; 0606 confirmation cannot be carried forward. Brightness stays deferred.

After a legal secure-exit completion, run exactly the 0605 two-image workload (including its existing same-page CP controls and fixed diagnostics), preserve raw BO/guards/all Fault snapshots and compare every pixel. A5 output still means First Render FAIL regardless of ZAP success. IRQ/Metal remain later independent milestones.
