# A650 同代公开项目审计（2026-11-03）

结论：alioth 已公开足以指导 A650 GX/CP 启动、真实 scratch 写入和后续离屏测试的实现；不能把其设备笔记、主机模型或提交存在等同于本项目实机验收。选择性采用 A6xx 的 OOB、CP_ME_INIT、PM4/fence 和测试判据，保留 kebab 0586 已验收的 GMU/HFI、16 KiB CPU 后端和 GPU 地址空间。当前 kebab First Execution / First Render 均未通过，本次审计不改变长期目标。

alioth `unixnu.lock` 未封住 GPU/kit 依赖，部分 UFS 锁定与 feeds 也不一致。旧 porting.toml 仍保留本地覆盖路径和已过时的分支描述，当前脚本与 feeds 已演进。因此公开 checkout 可以审阅及复现选定主机测试，但没有证明从全新 checkout 重建历史设备镜像。NativeAdreno CI 的 pre-build C/derive 检查通过也不能替代原生 C++ 完整构建。

## 七项比较与复用边界

| 范围 | 公开实现与证据 | 对 kebab 的处理 |
| --- | --- | --- |
| GX/GPUCC | alioth `package/pipa/A650Gmu.c` 先发送 HFI DCVS，再设置非 legacy GPU OOB bit30，轮询 ACK bit31，只 W1C 自己的 ACK；SPTPRAC bit6/7 清零是 GX power/clock on 指标。GPUCC/硬件表还有板级代码；NativeAdreno A650 文档承认部分 GCC/GPUCC 来源未固定。 | 0587 使用与已核对 vendor/mainline 一致的 OOB 位；新鲜检查 Root、IRQ、HFI、保留的 VM 和 GX 状态。保留现有频率档/BW/SN11，不照抄 SM8250-AC 的 perf7/670MHz；四次 HFI ACK 仍不等于目标资源效果。 |
| CP/SQE | `GpuProbe.cpp` 跳过 SQE 文件首 DWORD、拷贝并回读；先编程 SQE base，再启 SQE，A6xx CP_ME_INIT 为 opcode0x48、8 个 payload（0x2f、3、0x20000000、其余零），不用 A7xx THREAD_CONTROL/BV/pwrup list。NativeAdreno A650 文档说明该固件 payload31628B，旧版本0x93低于 mainline A650 0x95门槛。 | 只采用已交叉核对的 A650 序列；实际本地固件需独立测量、哈希和版本校验。现有单个16KiB SQE区不够，两个连续 RX 虚拟区合计32KiB可供受审的分段加载，尚未实现/验收；不得溢出或声称 SQE 已运行。 |
| SMMU/IOVA/BO | 两分支复用 ArmSmmu4K；alioth 记录真实 idle S2CR 0x203ff 与0x20000精确比较的兼容问题。NativeMemory 明确查询 CPU4K；新 kit API 依赖与 main 不同。 | 不移植其 allocator、TLBI、context 分配或全局寄存器策略。0586 的16KiB CPU/4KiB GPU、NormalNC目标/fence、WB clean PoC、CB1/ASID2/SMR2 SID0/mask401、GMU CB0均保持。 |
| Ring/IB/PM4 | 有 A6xx family 分支、IB 校验和 framed submit。70771a7 的 attach 已去掉 WPTR=0 写；当前实际6次编程，旧测试仍假设7次。部分旧文档的六字 prologue 与当前19字 table switch/四字 CCU invalidate不一致。HW_APRIV/NO_UPDATE 的新选择依赖硬件/固件。 | 从最小 kernel-owned ring/CP_MEM_WRITE 起步；不整包照搬 context replay、自动 scrub WAIT_FOR_IDLE 或 reset。现有 ring仅4KiB，不能照抄32KiB参数；需按实际大小生成控制字及边界验证。 |
| Fence/IRQ | A650 mask0x03d0e242、CP错误mask0xf7；A6xx使用 CP_EVENT_WRITE CACHE_FLUSH_TS event0x04及IRQ，而非A7xx BV fence。真实完成读取GPU写入的 fence，失败保留/poison。 | 完成判据要求新的GPU写入值、正确sequence、可见性和超时；IRQ计数只作独立观察，不替代完成。初期不引入未受审 fault ACK/CP reset/hang replay。 |
| First Execution / Render | alioth probe先把scratch清零，CP_MEM_WRITE写0xa6500c0d，提交等待并CPU回读；不是预填marker当成功。后续公开文档包含compute、纹理/渲染readback及Metal进程记录。NativeAdreno自身未提供该设备实机PASS。 | 先真实 CP init及新marker/fence，再离屏RGBA8目标像素校验；每步保留启动、原始回读、命令流/固件/原生哈希。不得因创建对象或无报错宣称首帧。 |
| Transport/Metal | 两者 `NativeAdrenoTransport` 都是cookie+结构体call回调，但 A650分支ABI v1/MaxBuffers16，70771a7 ABI v2/MaxBuffers128；Submit结构体分别416B/3104B。AdrenoMetal使用IOConnectCallStructMethod及特定service/type/selector与kit结构体。 | 回调签名可作适配层参考，实际ABI必须query/version/sizeof/selector逐项绑定。OS17的原版IOAcceleratorES别名及硬编码地址不适用于20H392。FirstRender之前不发布用户态GPU能力。 |

## 实机材料的可信范围

alioth 的 [porting.toml](https://github.com/FFT-infra/UniXNU-alioth/blob/f1883782125c9e4c6f5f3324c85ce980737caded/porting.toml) 和 [设备笔记](https://github.com/FFT-infra/UniXNU-alioth/blob/f1883782125c9e4c6f5f3324c85ce980737caded/docs/evidence/2026-10-29-gpu-gx-and-context.md) 包含具名模式/轮次、寄存器、scratch、IRQ、提交计数和readback错误数，明显比泛称“GPU可用”更有价值。审计分类为**作者报告的实机经验与摘录**。公开树没有封存所引用的完整 GPU 串口日志、每轮镜像/原生哈希及所有依赖绑定；笔记也修正过混合日志归属、空IB读回、等待过早退出等误判。因此不能独立确认其每项结果，亦不能把GUI/Metal进程启动等同无错合成或本项目PASS。

## 本次实际执行的 HOST 复现

未改动上游测试和生产源码，Git blob逐文件核对。Linux clang执行普通与 ASan/UBSan 两模式；仅采用明确建模的 IOKit/pexpert shim。PM4 依赖明确固定为官方 UniXNU/AdrenoPM4 282606b528b2595bc4274ea7490b62b323f35a5f，故这是选定模块复现，**不是历史完整依赖或原生内核复现**。

- NativeAdreno A650 的 family/hwinit/irq/cpinit/ring 共10次运行通过。
- alioth-ring IRQ 两次通过。
- alioth-ring CP 两次在严格 harness 下因新增 generation 字段的旧初始化器警告而编译拒绝。独立尾部采用真实板级 `-Wno-missing-field-initializers`（必须在 `-Wextra` 后）后编译通过，但两次运行均在旧写入次数断言 line81 失败。
- alioth-ring ring 两次编译通过、运行在 line249 失败：测试仍向第7次attach写入注入错误，而当前实现仅6次。没有修改测试制造PASS。

原始 `host-results/host-subset-result.json` SHA256 `18fed556bb71c082eee477ff4337af741d939e961c776b27b1a5c9215fd3d806`，总体 false；后续 `cpinit-board-flags-tail-v2/tail-result.json` 也如实 false。初次尾部flag排序错误的编译失败单独保留。以上测试没有访问设备，不能证明物理fence、CP或像素。
